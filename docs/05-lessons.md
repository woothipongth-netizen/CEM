# 5. บทเรียนจากการทดสอบ

สรุปจากการทดสอบจริง: คลิปรีวิวแนวตั้ง 30–60 วินาที จากฟุตเทจ 4K ~60 ไฟล์ + เสียงพากย์ภาษาไทย ทำซ้ำ 4 รอบจนได้ผลที่ดีมาก

## สิ่งที่เจ้าของงานติ และวิธีแก้ที่ใส่ไว้ในระบบแล้ว

| ปัญหา | สาเหตุ | แก้แล้วที่ |
|---|---|---|
| ไตเติ้ลมีแค่ตอนเปิด หลังจากนั้นเหลือแต่ซับ | ใส่ไตเติ้ลแค่ 3 วินาทีแรก | `titles` ในเทมเพลต ค้างบนจอทุกช่วง |
| ฟุตเทจติดช่วงตากล้องหันกล้องจะกดหยุด | ตัดรอบจุดที่ภาพคมสุด ซึ่งมักอยู่ท้ายคลิป, บางช็อตเริ่มที่วินาที 0 | `cut_shots.py` ข้าม 2 วิแรก/ท้าย และเลือกช่วงกล้องนิ่ง |
| ฟอนต์ไม่สวย | ระบบใช้ฟอนต์สำรอง | ฟอนต์จาก `brand.json` โหลดผ่าน npm |
| ซับไม่ตรงเสียง / ผิดคำ | ถอดเสียงไม่ได้ หรือโมเดลเล็กฟังผิด | ขอสคริปต์ก่อนเสมอ |
| ช้า | ทดลองเครื่องมือใหม่ระหว่างงาน (โมเดลถอดเสียงใหญ่, สร้างเพลงเอง) | โหมดเร็ว: ไม่ทดลองระหว่างงานจริง |
| เพลงที่สร้างเอง | MusicGen บน CPU ช้ามาก (>30 นาที) | กฎ: เพลงต้องมาจากเจ้าของงานเท่านั้น |

## ทดสอบขั้นสัมภาษณ์ + ออกแบบเทมเพลตเฉพาะร้าน (รอบที่ 1)

ใช้เวลารวม ~1 ชั่วโมง (ส่วนใหญ่เป็นเวลารอคำตอบ) สร้างเทมเพลตได้จริง แต่ผลยังไม่น่าพอใจ สิ่งที่แก้แล้ว:

| ปัญหา | แก้แล้วที่ |
|---|---|
| **ออกแบบจากคำตอบหมวดออกแบบอย่างเดียว** เจ้าของเลือกแนวก่อน-หลัง แต่ภาพตัวอย่างออกมาเป็นคลิปให้ความรู้ | docs/09 ขั้นที่ 2: สรุปโปรไฟล์ทั้งหมดเป็นข้อกำหนดออกแบบก่อน และภาพตัวอย่างต้องแสดงแนวคลิปหลัก |
| ชื่อธุรกิจข้ามได้ เทมเพลตเลยไม่มีชื่อร้าน | docs/07 ข้อ 1.2 บังคับตอบ ไม่มีตัวเลือกข้าม |
| ตัวเลือกน้อยเกินไป (อายุ, สิ่งที่กังวล, ปุ่มชวน, แพลตฟอร์ม, แนวคลิป, ลูกเล่น, โทนภาพ ฯลฯ) ต้องพิมพ์ใน "อื่นๆ" เอง | ข้อเลือกได้หลายข้อ แบ่งตัวเลือกเป็นหลายหน้า |
| Reels กับ Facebook รวมเป็นตัวเลือกเดียว | แยกเป็นคนละตัวเลือก |
| เสนอคำต้องห้ามให้เลือก / ถามข้อที่คำตอบชัดอยู่แล้ว (วิธีส่งงาน) | ข้อห้ามให้พิมพ์เองหรือ "ไม่มีคำเจาะจง" · ตัดคำถามวิธีส่งงาน (ส่งในแชท + ปุ่มบันทึกเสมอ) |
| "ถ้าร้านเป็นคน" ตอบยาก | เปลี่ยนเป็นเลือกจากภาพรวม 10 สไตล์ |
| ถามป้ายชื่อคนพูด / ใช้คำว่า "ช่าง" | ตัดออก ไม่มีป้ายชื่อในคลิป และไม่ใช้คำว่า "ช่าง" |
| ข้อความชิดขอบเกินไป อาจโดน UI ของแอปบัง | กำหนดพื้นที่ปลอดภัยใน docs/09 (เทมเพลตของร้านต้องทำตาม) |
| เพลงต้องส่งไฟล์ทุกครั้ง | รองรับคลังเพลงใน Drive (`brand.json` → `music_library`) |

## เครื่องมือที่ลองแล้ว

| เครื่องมือ | ผล | ใช้ไหม |
|---|---|---|
| Whisper small (faster-whisper) | ~5 นาที/นาทีเสียง ผิดหลายคำ ให้เวลารายประโยค | ✅ เมื่อไม่มีสคริปต์ |
| Whisper large-v3 | แม่น แต่ >20 นาทีบน CPU | ❌ |
| Thonburian Whisper medium (`Vinxscribe/biodatlab-whisper-th-medium-faster`) | คำถูกกว่า small มาก แต่ ~14 นาที ไม่มีเวลารายประโยค ตกคำท้ายช่วง 30 วิ | ⚠️ เฉพาะเมื่อขอความแม่นยำสูง ใช้คู่กับเวลาจาก small |
| video-understand `cull.py` | คัด 60 คลิปใน ~10 นาที ให้คะแนนคม/นิ่ง/แสง | ✅ |
| hyperframes-registry | สูตรทรานสิชัน, light leak, เกรน, lower third, แสงวิ่งบนตัวหนังสือ | ✅ อยู่ใน `review-motion` |
| embedded-captions | รับแค่คลิปคนพูดหน้ากล้องช็อตเดียว | ❌ กับคลิปเสียงพากย์หลายช็อต (ยืมสไตล์ `anchor` มาแทน) |
| media-use SFX | whoosh, sparkle ในตัว (ใช้เชิงพาณิชย์ได้) | ✅ |
| media-use เพลง (MusicGen) | ช้า คุณภาพพอใช้ | ❌ ห้ามใช้ |

## ปัญหาทางเทคนิคและวิธีแก้

| ปัญหา | วิธีแก้ |
|---|---|
| แนบคลิปใหญ่ในแชทไม่ได้ | ดึงจาก Drive ตรงๆ (`drive_download.sh`) |
| ตัวเชื่อม Drive อัปโหลดไฟล์ใหญ่ไม่ได้ | ส่งงานกลับทางแชท |
| render error `gsap ... reading 'timeline'` | `cdn.jsdelivr.net` ถูกบล็อก ใช้ GSAP ในเครื่อง (`setup.sh` เตรียมให้) |
| huggingface 403 / xethub | เพิ่ม `*.hf.co` ใน network |
| openai-whisper ดาวน์โหลดโมเดลไม่ได้ | ใช้ faster-whisper |
| faster-whisper error `metadata_errors` | แปลงเสียงด้วย ffmpeg ก่อน (`transcribe.py` ทำให้แล้ว) |
| ดิสก์เต็ม | ลบคลิปดิบที่ไม่อยู่ในแผน, ไฟล์ render เก่า, โมเดลที่เลิกใช้ |
| iPad เซฟคลิปจากแชทไม่ได้ | หน้า Artifact + capability `downloads` |
| ffmpeg concat ต่อไฟล์ไม่ได้ | ใช้ path เต็มใน list (แก้ใน `cut_shots.py` แล้ว) |

## ข้อควรระวังเวลาแก้เทมเพลต HyperFrames

- ห้ามแอนิเมต `letterSpacing` (ภาพกระตุก) ใช้ `scale`
- `fromTo` ที่ใช้กับ element เดิมหลายครั้ง ต้องใส่ `immediateRender: false`
- กล่อง `overflow: hidden` ที่ซ่อนตัวหนังสือไทย ต้องเผื่อขอบบน ไม่งั้นวรรณยุกต์ขาด
- ห้ามใช้ CSS animation (seek ไม่ตรงเฟรม) ใช้ GSAP `tl.set` แทน
- จับเวลาที่ `<video>` หรือ wrapper อย่างใดอย่างหนึ่ง ห้ามทั้งคู่
- แสงวาบสีขาวเต็มจอ (flash) ให้สูงสุดไม่เกิน 0.8 ไม่งั้นแสบตา
- ทดสอบด้วย `npx hyperframes snapshot --at ...` ก่อน render ทุกครั้ง ประหยัดเวลามาก
- กล่องที่ใช้ `z-index` ข้างใน (เช่น ช่วงเทียบก่อน-หลัง) ต้องใส่ `isolation: isolate` ที่กล่องแม่ ไม่งั้นทับซับและหัวข้อ
- ตัวแปร CSS ที่ตั้งบน `#root` ต้องแก้ด้วย `#root.<คลาส>` ไม่ใช่ `.<คลาส>` (id ชนะคลาส ค่าจะไม่เปลี่ยน)
- ซูมเน้นจุดในเทมเพลตที่มีกรอบ: ซูมภาพข้างในกรอบ อย่าซูมตัวกรอบ (กรอบจะขยายล้น)

## รอบเร่งความเร็ว (~64 นาที → ~20 นาที ต่องาน)

| เปลี่ยนอะไร | ผล |
|---|---|
| ดึงฟุตเทจพร้อมทำเฟรมหลัก 720p (`fetch_footage.sh`) | ดึง + เตรียมภาพรวม 77 คลิป ~4 นาที |
| ภาพรวมจากเฟรมหลัก ติดชื่อไฟล์ (`contact_sheet.py`) | 77 คลิป 33 วินาที (เดิมคัดจาก 4K 13 นาที) และไม่จดชื่อผิดอีก |
| วัดกล้องสั่นจาก 4K เฉพาะคลิปในแผน (`check_shots.py`) | 14–19 คลิป ~3–4 นาที |
| สตอรีบอร์ดมีเลขช็อต (`plan_sheet.py`) | เจ้าของงานสั่งแก้ด้วยเลข เช่น "เปลี่ยนช็อต 7" |
| `cut_shots.py --curves` ใช้ค่าจาก check_shots + ตัดพร้อมกัน 4 ช็อต | 19 ช็อต 6.4 → 2.2 นาที, แก้บั๊กส่วนเผื่อหัวช็อตล้ำเข้า 2 วินาทีแรก |
| ถอดเสียงทีละท่อนตามจังหวะหายใจ (`transcribe.py`) | ได้ครบทุกประโยครอบเดียว ~0.5–1.5 นาที (เดิมเพี้ยนกลางคลิปและตกท้าย) |
| ชื่อร้านที่การ์ดจบย่อเองตามความยาว (`build.py`) | ชื่อยาวไม่ล้นจอ |

### ลองแล้วไม่ช่วย (ไม่ต้องลองซ้ำ)
- ย่อฟุตเทจทั้งหมดเป็น 720p ก่อนคัด: ช้าพอกัน (~13 นาที) เพราะยังถอดรหัส 4K ทุกเฟรม
- ย่อไฟล์ระหว่างดาวน์โหลด: เร็วขึ้นแค่ ~1 นาที
- คัดจากเฟรมหลักอย่างเดียว: จับกล้องสั่นไม่ได้เลย (พลาด 8 จาก 8 คลิป) ต้องใช้ `check_shots.py`
- skill ตัดต่อจาก GitHub: ไม่มีตัวไหนแก้เรื่องความช้า
- ตัดไฟล์เล็ก 720p ทิ้ง: ประหยัดแค่ ~30 วินาที และยังต้องใช้กับหน้าปุ่มบันทึก

### ข้อควรรู้
- ป้าย SOFT เทียบกับ 80% ของชุดเดียวกัน ฟุตเทจหน้าคมแต่พื้นหลังละลายได้ป้ายนี้บ่อย ดูภาพจริงก่อนตัดทิ้ง
- ป้ายสั่น (jitter > 0.355) ใช้ตัวเลขตายตัวได้ ทดสอบกับฟุตเทจ 2 ชุดแล้ว
- ส่วนที่ช้าที่สุดตอนนี้คือ render (~4.5 นาที / คลิป 37 วิ, ~7.5 นาที / 61 วิ)

## บทเรียนจากคลิปแรกของเทมเพลตร้าน (ความเห็นเจ้าของ)

- เส้นลายมือใต้หัวข้อที่วาดครั้งเดียวแล้วนิ่ง = "ไม่มี motion" → ต้องมีประกายวิ่งตามเส้นเป็นระยะ และขยับเบาๆ ตลอดช่วง
- หัวข้อเล็กติดมุมจอ มองไม่ชัด → หัวข้อกลางจอด้านบน ตัวใหญ่ (ถ้าทับหน้าใช้ `pos: low`)
- คู่ภาพก่อน-หลังที่ถ่ายคนละระยะ/มุม เทียบไม่สวย → คัดคู่ด้วย `match_before_after.py` เสมอ
- ตอนจบ: ชื่อร้าน + ปุ่มชวนไว้บน ซับไว้ล่าง เว้นกลางจอให้เห็นภาพลูกค้าหลังทำ

## ผลทดสอบชุดคำถามใหม่ + คลิปแรก (สัมภาษณ์ → ออกแบบ → ตัดคลิปโหมดอัตโนมัติ)

| ขั้น | เวลา | ผล |
|---|---|---|
| สัมภาษณ์ธุรกิจ 6 หมวด | ~21 นาที | ใช้ได้ การแบ่งหน้าข้อเลือกหลายข้อทำงานจริง |
| คำถามออกแบบ + ภาพรวม 10 สไตล์ | ~20 นาที | รอบแรกภาพรวมต่างกันแค่สี ต้องทำใหม่ |
| สร้างเทมเพลต (11 สไตล์ × 3 แนว) | ~12 นาที | ผ่าน lint ทุกสไตล์ |
| ตัดคลิปแรก 39 วิ ฟุตเทจ 77 คลิป 13GB | ~21 นาที | เจ้าของให้ "ค่อนข้างดี" |

ปัญหาที่เจอ → แก้แล้ว (รายละเอียดใน docs/07, docs/09, docs/04)
- ภาพรวมสไตล์ต่างกันแค่สี → ต้องต่างที่เลย์เอาต์อย่างน้อย 3 อย่าง
- ตอบขัดกันในข้อหลายหน้า, เลือกครบทุกข้อ, ข้อ 3 หน้าถูกแยกข้ามรอบ → กติกาอ่านคำตอบ + ถาม "ข้อไหนสำคัญที่สุด" + แผนการถามรายครั้ง
- ตัวอย่างในคำถามมาจากคำตอบเดิม (ชี้นำ) → ห้าม
- "ลายมือ" ขัดกับกฎฟอนต์ → `brand.json` font_hand เป็นฟอนต์รอง
- เพลง → ตัวเลือก "ใส่เพลงเองในแอป" (ค่าเริ่มต้น)
- โหมดอัตโนมัติยังถามสรุปเวลา → ห้ามถามอะไรเลย ใส่สรุปเวลาในข้อความส่งงาน
- คลิปแรก: หัวข้อเล็กติดมุม, เส้นลายมือไม่ขยับ, คู่ภาพก่อน-หลังคนละระยะ, ตอนจบไม่เว้นกลางจอ, ซับ 2 บรรทัดยาวเกิน
  → ข้อกำหนดเทมเพลตใน docs/09 + `match_before_after.py` + `split_captions.py` + คำถาม 4.5
