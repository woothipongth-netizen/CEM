# 4. ขั้นตอนตัดคลิป: โหมดเร็ว + ถามก่อนทำ

หลักคือ **ขอของให้ครบตั้งแต่ต้น ไม่ทดลองระหว่างงาน และให้เจ้าของงานเห็นแผนก่อน render**
คลิป 40–60 วินาทีจากฟุตเทจ 4K ~70 คลิป ใช้ราว 20–25 นาที (ไม่นับเวลารอคำตอบ)

## ฝั่งเจ้าของงาน: สิ่งที่ต้องส่ง

1. **ลิงก์โฟลเดอร์ Google Drive** ที่มีฟุตเทจดิบทั้งหมด (4K ได้ ไม่ต้องย่อ) และไฟล์เสียงพากย์
2. **สคริปต์บทพากย์** (พิมพ์หรือวางในแชท) ทำให้ซับถูก 100% และไม่ต้องรอตอบเรื่องคำที่ไม่แน่ใจ
3. **เพลง** (ข้ามถ้าโปรไฟล์บอก "ใส่เพลงเองในแอป"): ไฟล์ (mp3/m4a), ชื่อเพลงจากคลังเพลงใน Drive (`brand.json` → `music_library`) หรือ "ให้ Claude เลือก" (เลือกจากคลังของร้านก่อน ไม่มีที่เหมาะค่อยหาจาก Mixkit) Claude จะไม่สร้างเพลงหรือหาจากเว็บอื่น
4. ความยาวคลิป และแนวคลิป หรือพิมพ์ว่า "ตัดสินใจเองได้เลย"

ตัวอย่างข้อความสั่งงาน:
> ตัดคลิปรีวิว 60 วิ ฟุตเทจกับเสียงพากย์อยู่ที่ <ลิงก์> สคริปต์ตามนี้ ... ใช้เพลงที่แนบมา

## ฝั่ง Claude: ขั้นตอน

งานแต่ละชิ้นเก็บใน `work/<ชื่องาน>/` (Git ข้ามโฟลเดอร์นี้):
```
work/<ชื่องาน>/
├── ids.txt          ← รายการไฟล์ Drive
├── raw/             ← ฟุตเทจดิบ 4K
├── kf/              ← เฟรมหลัก 720p (ใช้ดูภาพรวม)
├── sheets/          ← ภาพรวมติดชื่อไฟล์ + kf.json
├── vo/              ← เสียงพากย์ + transcript
├── audio/           ← เพลงที่ได้รับ + mix.wav
├── plan.json        ← แผนช็อต
├── plan_sheet.png ← สตอรีบอร์ดมีเลขช็อต (ส่งให้เจ้าของงาน)
├── check.json       ← ผลวัดละเอียด + ค่าการเคลื่อนไหว (cut_shots ใช้ต่อ)
├── shots-motion/    ← ช็อตที่ตัดแล้ว + check_all.jpg
├── content.json     ← หัวข้อ ซับ ทรานสิชัน
├── comp-motion/     ← โปรเจกต์ HyperFrames
└── out/             ← ไฟล์ส่งงาน
```

**รองานเบื้องหลังด้วยไฟล์สัญญาณ** เช่น `until [ -f work/<งาน>/.fetch_done ]; do sleep 5; done`
ห้ามใช้ `pgrep -f <ชื่อสคริปต์>` เพราะคำสั่งรอจะเจอตัวเองและรอไม่จบ

### ขั้น 0: เตรียมเครื่อง (~3 นาที)
```bash
bash scripts/setup.sh
```
อ่าน `brand.json` ถ้ายังเป็น `xxxx` ให้ถามข้อมูลแบรนด์ก่อน

### ขั้น 1: ดึงไฟล์ + ถอดเสียง (พร้อมกัน, ~4 นาที / 13GB)
1. ใช้ตัวเชื่อม Google Drive: `search_files` ด้วย `parentId = '<folder id>'` ตาม `pageToken` จนครบทุกหน้า
   (รวมโฟลเดอร์ย่อยด้วย) เขียน `ids.txt` บรรทัดละ `<ชื่อไฟล์> <file id>` ข้ามไฟล์ที่ไม่ใช่วิดีโอ (.DS_Store)
2. ดึงเสียงพากย์ก่อน (`scripts/drive_download.sh`) แล้วรันสองอย่างนี้ **พร้อมกัน** ในเบื้องหลัง:
```bash
python3 -I scripts/transcribe.py work/<งาน>/vo/vo.mp3 work/<งาน>/vo          # ข้ามถ้ามีสคริปต์
scripts/fetch_footage.sh work/<งาน>/ids.txt work/<งาน>
```
- **มีสคริปต์:** หาเวลาแต่ละประโยคจากจังหวะหยุดแทนการถอดเสียง
  ```bash
  ffmpeg -i vo.mp3 -af silencedetect=n=-35dB:d=0.25 -f null - 2>&1 | grep silence_
  ```
- **ไม่มีสคริปต์:** `transcribe.py` ตัดท่อนตามจังหวะหยุดและถอดทีละท่อน แก้คำผิดจากบริบท จดคำที่ไม่แน่ใจไว้ถามในขั้น 3
  ห้ามใช้ large-v3 (ช้าเกิน) ส่วน Thonburian ใช้เฉพาะเมื่อเจ้าของงานขอความแม่นยำสูงและรอได้

### ขั้น 2: ภาพรวม + เลือกช็อต + วัดละเอียด (~5 นาที)
```bash
python3 -I scripts/contact_sheet.py work/<งาน>
```
เปิดดู `sheets/sheet_*.png` ทุกแผ่น ทุกช่องติดชื่อไฟล์ เรียงตามลำดับที่ถ่าย ให้จดชื่อไฟล์ลง `plan.json` ตามที่เห็นบนภาพ
(ดู [templates/review-captions/plan.example.json](../templates/review-captions/plan.example.json))
- ป้าย SOFT = เบลอกว่าคลิปส่วนใหญ่ในชุด ถ้าพื้นหลังละลายแต่หน้าคม ยังใช้ได้
- คลิปพื้นหลังมืดได้คะแนนต่ำ แต่ถ้าเป็นช็อตสำคัญ (เช่นผลงานหลังทำ) ยังต้องใช้
- ภาพรวมนี้ **วัดกล้องสั่นไม่ได้** ต้องวัดต่อ:
```bash
python3 -I scripts/check_shots.py work/<งาน>/plan.json work/<งาน>/raw work/<งาน>
```
ช็อตไหนขึ้น "สั่น" ให้เปลี่ยนเป็นคลิปสำรองใน `plan.json` แล้วรันคำสั่งเดิมซ้ำ (วัดเฉพาะคลิปใหม่ ~10 วินาที/คลิป)

**ช่วงเทียบก่อน-หลัง: ต้องคัดคู่ภาพที่มุมกล้องและระยะเดียวกัน** (เจ้าของถ่ายมุมเดิมไว้ทั้งก่อนและหลัง) ห้ามเดาจากภาพรวม
```bash
python3 -I scripts/match_before_after.py work/<งาน> --before <คลิปก่อนทำ...> --after <คลิปหลังทำ...>
```
ดู `match_before_after.jpg` แล้วใส่ `"start"` ของคู่ที่เลือกใน `plan.json` (ทั้งช็อตก่อนและหลัง) และ `before_at` / `after_at` ใน `compare` (~10 วินาที)

### ขั้น 3: ส่งแผนให้เจ้าของงานดู ⏸️ รอคำตอบ (เฉพาะโหมด "ดูระหว่างทาง")

ดู `โหมดการทำงาน` ใน `business-profile.md` ถ้าเป็น **อัตโนมัติ** ให้ทำสตอรีบอร์ดเก็บไว้ แล้วไปขั้นต่อไปเลย
ตอนส่งงานไฟนอล แนบสตอรีบอร์ด + สรุปสิ่งที่ตัดสินใจ + คำในซับที่เดา เจ้าของสั่งแก้ด้วยเลขช็อตได้เหมือนกัน

ทำสตอรีบอร์ดแล้วส่งรูปนี้พร้อมตารางในแชท:
```bash
python3 -I scripts/plan_sheet.py work/<งาน>
```
`plan_sheet.png` = ภาพเดียวเห็นทุกช็อต มีเลขช็อตตัวใหญ่ เวลา ชื่อไฟล์ และ `note` (เขียน note สั้นๆ ไม่เกิน ~25 ตัวอักษร)

ตารางในแชท **ใส่เลขช็อตทุกแถว** ให้ตรงกับเลขบนสตอรีบอร์ด (ช็อต 1 = แถวแรกใน `plan.json`)
เจ้าของงานสั่งแก้ด้วยเลขได้เลย เช่น "เปลี่ยนช็อต 7" "สลับ 3 กับ 4" "ช็อต 10 สั้นลง"
หลังแก้ ทำสตอรีบอร์ดใหม่ เลขช็อตจะเรียงใหม่ตามแผนล่าสุด ให้บอกเจ้าของงานถ้าเลขเปลี่ยน
- ลำดับช็อต: #เลข → เวลา → ภาพอะไร → ตรงกับคำพูดไหน
- หัวข้อของแต่ละช่วง (หัวข้อต้องค้างบนจอตลอดคลิป)
- ซับทั้งหมด (ทำเครื่องหมายคำที่เดา)
- เพลงที่จะใช้ และช่วงไหนของเพลง (ถ้า Claude เลือก: บอกชื่อเพลง ความเร็ว และเหตุผลสั้นๆ)

แก้ตามที่เจ้าของงานบอก แล้วไปต่อ **โหมดดูระหว่างทาง: อย่า render ก่อนได้คำตอบ**

สคริปต์จะเตือนถ้า `start` ที่ใส่เองล้ำเข้า 2 วินาทีแรก/ท้ายของคลิป
หลังได้ช็อตครบ ลบคลิปดิบที่ไม่ได้ใช้ เพื่อคืนพื้นที่ดิสก์

### ขั้น 5: เพลงและเสียง (~2–3 นาที)

**5.1 เลือกเพลง (ถ้าเจ้าของให้ Claude เลือก หรือขอเพลง)** ทำตั้งแต่ขั้น 3 เพื่อวางจุดตัดตามจังหวะได้

**ถามเพิ่มก่อนหาเพลง** (AskUserQuestion ครั้งเดียว 3 ข้อ · โหมดอัตโนมัติไม่ถาม: เลือกจากแนวคลิปและโทนในโปรไฟล์ แล้วบอกในข้อความส่งงาน)

| ข้อ | คำถาม | ตัวเลือก → ใช้กับเครื่องมือ |
|---|---|---|
| 1 | เพลงทำหน้าที่อะไรในคลิป | **เปิดคลิปแรง** ดึงคนดูตั้งแต่วินาทีแรก → `moments --style front` · **ก่อน-หลัง** ช่วงก่อนดนตรีเบาแต่จังหวะไต่ขึ้น แล้วปะทะตอนภาพหลังขึ้น → `moments --style drop` · **พื้นหลังสม่ำเสมอ** ไม่แย่งเสียงพูด → `pick` |
| 2 | อารมณ์เพลง | หรู ละมุน (Mixkit: `elegant` `dreamy` `calm`) · สนุก สดใส (`happy` `upbeat`) · มั่นใจ มีพลัง (`confident` `energetic` `dynamic`) · แฟชั่น / ฟังก์ (`house` `funk` `edm`) |
| 3 | หาเพลงจากไหน | คลังเพลงของร้านก่อน · Mixkit · ทั้งสองที่ |

แล้วทำคลิปฟังตัวอย่าง 3–5 เพลงให้เลือก (ทำแบบนี้แล้วเจ้าของเลือกง่าย ทดสอบแล้ว):
```bash
python3 -I .agents/skills/mixkit-sfx/scripts/mixkit.py music <อารมณ์>     # ถ้าใช้ Mixkit: ค้น 2–4 อารมณ์ แล้ว getmusic ลง work/<งาน>/music-pool
python3 scripts/music_index.py moments work/<งาน>/music-pool --style drop -n 5 --json work/<งาน>/moments.json
python3 scripts/music_index.py preview work/<งาน>/moments.json work/<งาน>/music-preview.mp4
```
- `drop`: ในคลิปตัวอย่างแต่ละเพลงเป็น "BEFORE" 6 วินาที → "AFTER" 4 วินาที จุดปะทะอยู่ตรงรอยต่อ ใช้จริงตั้ง `BGM_START = จุดปะทะ − วินาทีที่ภาพหลังขึ้น`
  (เทมเพลต `review-compare`: ภาพหลังขึ้นตอนม่านปาด / เส้นเลื่อนไปสุด)
- `front`: ตั้ง `BGM_START = จุดเพลงเข้าแรง` คลิปเปิดมาเพลงเข้าเลย
- คัดเพลงโทนเศร้า/หลอนออกเอง แม้คะแนนสูง (ดูแท็กจาก `mixkit.py music`)

**พื้นหลังสม่ำเสมอ** ใช้ `pick`:
```bash
# วัดคลังเพลงครั้งแรก (ครั้งต่อไปวัดเฉพาะเพลงใหม่) แล้วเรียงเพลงที่เข้ากับคลิป
python3 scripts/music_index.py scan work/music-library
python3 scripts/music_index.py pick work/music-library/music_index.json --length <ความยาวคลิป> --pace fast|medium|slow --mood soft|bright
```
- `pace` จากโปรไฟล์: จังหวะ "เร็ว กระชับ" = fast · "ช้า นุ่มนวล" = slow · ไม่ระบุ = medium
- `mood`: โทนหรู/นุ่ม/อบอุ่น = soft · สนุก/สดใส = bright
- คลังของร้านไม่มีเพลงที่เข้า: หาจาก Mixkit ด้วย skill `mixkit-sfx` (`music <อารมณ์>` แล้ว `getmusic`) ใช้เชิงพาณิชย์ได้ ไม่ต้องใส่เครดิต
  เพลงที่ใช้แล้วชอบ บอกเจ้าของเก็บเข้าคลังเพลงใน Drive ของร้าน (ห้าม commit ไฟล์เพลงลง repo)

**5.2 ตัดภาพตามจังหวะ** หลังได้จุดเปลี่ยนหัวข้อ/ช็อตจากแผน
```bash
python3 scripts/beats.py <เพลง> --length <ความยาว> --snap "<จุดเปลี่ยนหัวข้อและช็อต>" --tol 0.25 --suggest-start
```
- ได้วินาทีเริ่มเพลงที่ดีที่สุด + จุดตัดใหม่ที่ตรงจังหวะ (ขยับไม่เกิน 0.25 วินาที) แก้ `at`/`dur` ในแผนช็อตและ `start`/`end` ของหัวข้อตามนั้น
- **ภาพต้องตรงกับคำพูดก่อนเสมอ** จุดไหนขยับแล้วภาพไม่ตรงคำพูด ให้คงเดิม
- ทดสอบแล้ว: เพลง 123 BPM จุดตัด 5 จุด ห่างจังหวะเฉลี่ยเหลือ 0.09 วินาที

**5.3 มิกซ์**
```bash
SFX_DIR=<คลัง SFX ของร้าน> BGM_LEVEL=mid BGM_START=<วินาทีเริ่มเพลงจาก 5.2> \
  scripts/mix_audio.sh vo.mp3 <เพลง หรือ none> work/<งาน>/audio/mix.wav <ความยาว> "<เวลาเปลี่ยนหัวข้อ>" <เวลาการ์ดจบ>
```
- `BGM_LEVEL`: `low` เพลงเบา (คนพูดตลอด) · `mid` ค่าเริ่ม · `high` เพลงเด่น (พูดน้อย / คลิปภาพล้วน)
- เพลงลดเสียงเองตอนมีคนพูด และดังขึ้นช่วงเงียบ (`BGM_GAP_BOOST=0` ให้ดังเท่าๆ กันตลอด)
- เจ้าของบอก "เพลงดังไป/เบาไป" → เปลี่ยน `BGM_LEVEL` แล้วมิกซ์ใหม่ ไม่ต้อง render ภาพใหม่ (แค่รวมเสียงใหม่กับวิดีโอเดิม)

### ขั้น 6: ประกอบและ render (~5–8 นาที)
เขียน `content.json` (ดู [templates/review-motion/content.example.json](../templates/review-motion/content.example.json)):
- `hook` ข้อความเปิด 3 วินาทีแรก
- `titles` หัวข้อค้างบนจอทุกช่วง
- `captions` ซับ (`*คำ*` = สีแบรนด์) **บรรทัดเดียว สั้น ไม่ใช้ `|`** ความยาวตามโปรไฟล์ `ความยาวซับ`
  (สั้น 1 บรรทัด ≤20 ตัวอักษร · สั้นมาก ≤12 ตัวอักษร · ไม่ได้ตอบ = 20) เขียนซับตามเสียงแล้วเว้นวรรคตรงจุดหยุดหายใจ แล้วรัน
  `python3 -I scripts/split_captions.py work/<งาน>/content.json --max 20` ตัดเป็นท่อนสั้นให้อัตโนมัติ
  ห้ามซับ 2 บรรทัด ไม่ว่าเจ้าของเลือกคำตอบไหน (เจ้าของบอกว่า 2 บรรทัด "ดูติดเยอะเกินไป")
- `lower_thirds` ป้ายชื่อคนพูด: **ไม่ใช้** (ไม่ใส่ป้ายชื่อในคลิป)
- `transitions` กำหนดทรานสิชันเฉพาะจุด: `blur` `slide` `zoom` `leak` `flash` `cut`
- `end_card.start` เวลาเริ่มการ์ดจบ (ชื่อร้านและปุ่มดึงจาก `brand.json`, ใส่ `"brand"` เพื่อใช้ชื่ออื่นเฉพาะคลิป ชื่อยาวจะย่อตัวอักษรเอง)

```bash
python3 -I templates/review-motion/build.py work/<งาน>/content.json work/<งาน>/comp-motion
cd work/<งาน>/comp-motion && npx hyperframes lint
```
